Week 3

Probability

Introduction

This week we will begin by playing the rock-paper-scissors game below.

  1. Choose one if the three options (Rock, Paper or Scissors) then click Submit.
  2. The computer will do the same.
  3. If you beat the computer you get one point. If the computer wins, then you lose point. A draw is worth 0 points.
  4. After the first game is completed, click Next game.
  5. The winner is whoever has the most points after 10 games.

How did you go? Did you finish ahead of the computer, or did the computer finish ahead of you?

At first, rock-paper-scissors looks like a simple game of chance. There are three possible choices, and each choice beats one option, loses to one option, and draws with itself. If both players choose completely at random, neither player should have a long-run advantage. Over many rounds, we would expect wins, losses, and draws to occur at roughly similar rates.

But the computer in this game was not choosing completely at random.

Click the see the computer’s strategy
  • if it won the previous round, it stayed with the same choice;
  • if it lost the previous round, it shifted to the next choice in the sequence (rock -> paper -> scissors -> rock -> etc.);
  • if the previous round was a draw, it chose randomly.

This is called a win-stay, lose-shift strategy.

If you chose randomly, the computer may have been difficult to beat. But if you paid attention to the previous round, you may have started to predict what the computer was likely to do next. The computer’s choices were not random in the same way as flipping a coin or rolling a fair die. They had structure.

This is the important statistical idea. The sample space stayed the same in every round. But the process that generated the computer’s choice changed from a purely random process to a patterned process. Once there is a pattern, the previous outcome can contain useful information about the next outcome.

So the first question might be:

What is the probability of winning rock-paper-scissors?

But the better statistical question is:

Are the choices being generated randomly, or is there a pattern in the process?

In this tutorial, we will:

  1. Define the sample space for rock-paper-scissors
  2. Use R to simulate random choices from that sample space
  3. List all possible outcomes from one round of the game
  4. Calculate the probability of winning, losing, or drawing when both players choose randomly
  5. simulate many rounds to compare theoretical probability with long-run results
  6. Introduce a simple win-stay, lose-shift strategy
  7. Compare random play with patterned play
  8. Use the results to think about how the process generating outcomes changes the probabilities we observe

Part 2: Coding the rules of rock-paper-scissors

Now we need to teach R the rules of the game.

The rules are:

  • Rock beats Scissors.
  • Scissors beats Paper.
  • Paper beats Rock.
  • If both players choose the same option, the round is a draw.

We will write a function that takes two choices as inputs and returns the result of the round.

Homework: Adding a strategy to the simulation

In the tutorial, we simulated rock-paper-scissors under a simple random model. In that model, both players chose randomly on every round. But in the game you played at the start, the computer did something different. It used a simple strategy:

  • if the computer won the previous round, it stayed with the same choice;
  • if the computer lost the previous round, it switched to the next choice in the sequence;
  • if the previous round was a draw, it chose randomly.

This is called a win-stay, lose-switch strategy. Your task is to modify the simulation so that the computer uses this strategy.

Write a simulation where:

  1. Player A chooses randomly each round.

  2. The computer chooses randomly in the first round.

  3. From the second round onward, the computer uses the result of the previous round:

    • if the computer won, it repeats its previous choice;
    • if the computer lost, it switches to the next option;
    • if the round was a draw, it chooses randomly.

  4. Simulate 10,000 rounds.

  5. Count the number and proportion of times that Player A wins, the computer wins, and the round is a draw.

switch_choice <- function(choice) {

Hint 4: You need memory

This simulation is different from the random simulation because the computer’s current choice depends on what happened in the previous round.

That means you need to keep track of:

  • the computer’s previous choice;
  • the result of the previous round.

A useful structure is to create an empty results table first.

results <- tibble(
  round = 1:n_rounds,
  player_a = NA_character_,
  computer = NA_character_,
  result = NA_character_
)

Hint 5: Use a loop

Because each round depends on the previous round, a for loop is a reasonable approach.

Here is a starting structure.

for (i in 1:n_rounds) {
  
  player_a <- choose_random()
  
  if (i == 1) {
    
    computer <- ...
    
  } else {
    
    previous_computer <- results$computer[i - 1]
    previous_result <- results$result[i - 1]
    
    computer <- case_when(
      previous_result == "Computer wins" ~ ...,
      previous_result == "You win" ~ ...,
      previous_result == "Draw" ~ ...
    )
  }
  
  result <- rps_result(player_a, computer)
  
  results$player_a[i] <- player_a
  results$computer[i] <- computer
  results$result[i] <- result
}

Extension

Modify the simulation so that Player A does not choose randomly. Instead, Player A should try to predict the computer’s next move. If Player A can predict what the computer is likely to choose, Player A should choose the option that beats it. For example, if Player A predicts that the computer will choose Rock, Player A should choose Paper.
